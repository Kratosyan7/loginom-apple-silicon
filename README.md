# Loginom Community на Apple Silicon

Loginom Community выпускается для Windows и Linux. Сборки под macOS нет, а Linux-версия —
это бинарник под x86-64, который на процессорах Apple не запускается.

Здесь лежит обвязка, которая решает проблему: Linux-контейнер на arm64, где вся
инфраструктура работает нативно, а само приложение транслируется через
[box64](https://github.com/ptitSeb/box64). Интерфейс отдаётся по VNC и открывается
встроенным в macOS «Общим экраном».

## Чего здесь нет

**Файлов самой программы.** Их распространение запрещено лицензией Loginom (п. 5.5 и 5.8),
поэтому скачивать дистрибутив нужно самостоятельно — это бесплатно.

## Установка

Нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
git clone https://github.com/Kratosyan7/loginom-apple-silicon.git
cd loginom-apple-silicon
```

Скачайте Linux-версию Loginom Community с [loginom.ru/community](https://loginom.ru/community),
положите архив в эту папку и распакуйте:

```bash
tar -xf loginom-community-*.tar.gz
./run.sh
```

Первый запуск собирает образ — это 5–10 минут. Дальше контейнер стартует за секунды.

## Как пользоваться

| | |
|---|---|
| Подключение | `vnc://localhost:5900` |
| Пароль | `loginom` |
| Общая папка | `~/Loginom` на маке ↔ `/data` внутри |

Окно остаётся белым первые 60–90 секунд после запуска, пока инициализируется
встроенный браузерный движок. Это не зависание.

Чтобы открыть свой файл в Loginom, положите его в `~/Loginom` и в диалоге выбора
нажмите **Ctrl+L**, затем введите `/data`.

```bash
docker stop loginom              # остановить
docker start loginom             # запустить снова
docker exec loginom screenshot   # снимок экрана в общую папку
docker logs loginom              # вывод приложения
```

Буфер обмена синхронизируется в обе стороны: копируете на маке через ⌘C, вставляете
в Loginom через **Ctrl+V** (внутри Linux именно Ctrl, не ⌘).

## Почему именно так

Очевидный путь — включить Rosetta в Docker Desktop — не работает: встроенный в Loginom
движок Chromium вызывает `eventfd` (системный вызов 284), которого в Rosetta нет,
и приложение падает сразу при старте. Подмена символа через `LD_PRELOAD` не спасает —
вызов делается в обход библиотеки C.

Остаётся эмуляция. Стандартный QEMU работает, но транслирует вообще всё, включая
X-сервер и VNC-сервер. Схема в этом репозитории эмулирует только само приложение,
а инфраструктуру держит нативной. Замер на 12-ядерном Apple Silicon:

| | QEMU (amd64) | box64 (arm64) |
|---|---|---|
| процессорное время за 300 с после старта | 116 с | 16 с |
| нагрузка в простое | 5.06 % | 0.11 % |
| память | 553 МБ | 1.47 ГБ |

Мерились запуск и выход в простой, не обработка данных.

### Что пришлось учесть

Четыре подводных камня, каждый со своей причиной:

- box64 оборачивает **нативные** arm64-версии GTK, GLib, ATK и Wayland, поэтому в образ
  ставятся обе архитектуры сразу, а `-dev` пакеты нужны ради безверсионных симлинков
  вида `libgtk-3.so`, которые box64 ищет по имени;
- box64 перезапускает себя через `execv` по `argv[0]`, а `execv` не ищет в `PATH` —
  вызывать его нужно абсолютным путём;
- в штатной обёртке box64 для tcmalloc нет символов `MallocExtension_*`, которые требует
  Loginom, поэтому поставляемая x86-64 версия принудительно эмулируется через
  `BOX64_EMULATED_LIBS`;
- `x11vnc -ncache` ломает картинку в «Общем экране» macOS — клиент не поддерживает это
  расширение и показывает служебную часть буфера кадра.
